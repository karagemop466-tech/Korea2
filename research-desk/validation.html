02 / COMPETITION DESIGN

A leaderboard built for skill

SCORING

Reward forecast quality, not lucky wins.

For each eligible common event, use score improvement = baseline log loss − model log loss. Higher is better. Rank only candidates that pass every gate; report the matched sample and interval. Require a pre-registered minimum sample by market before evaluation; no minimum has been set or tested.

REWARDS

Keep the prize pool hypothetical.

Proposed: award fixed non-cash research credits to the top eligible strategy after the locked evaluation period. If none passes, award nothing. Pool size, tie rules and eligibility must be fixed before a future contest; none currently exists.

Evaluation protocol

  1. Register candidates, eligible event universe, timestamps, frozen market baseline and metrics before observing outcomes.
  2. Use expanding training windows, time-ordered validation and a final untouched holdout. Group all legs in a game; preserve forecast-time availability and archive corrections.
  3. Calibrate on a separate earlier window. Never tune on the final holdout. Require forecasts for all eligible events even when the betting policy abstains; compare the same events to avoid cherry-picking. Missing competition forecasts make a candidate ineligible.
  4. Quantify uncertainty with paired game-block resampling and account for candidate selection using nested evaluation or a multiple-testing procedure specified in advance. Report realized ROI as secondary, not proof of skill.

Log loss for binary outcome y and forecast p is −[y log(p) + (1 − y) log(1 − p)]; probabilities must be strictly between 0 and 1. Loss comparisons require identical settled event definitions; pushes and voids need separate handling. Metrics documentation ↗

These controls reduce overfitting and luck-driven selection; they cannot remove randomness or guarantee future performance. NIST on forecasting ↗
