REVIEW WORKFLOW

How a suggestion becomes a change

  1. Triage

    Read the suggestion, its evidence and its cost. Nothing is implemented at this step.

  2. Check the evidence

    Open the linked source and the referenced data file. A suggestion with an unverifiable claim is sent back, not approved.

  3. Choose a path

    Accept, park, or reject. Exactly one path per suggestion, recorded in the register so the next session cannot silently reopen it.

  4. Assign a gate

    Say which of the ten gates the change is meant to move. A change that moves no gate is parked.

  5. Implement behind the gate

    Ship it with a check that fails if the gate regresses. No strategy page updates on an unapproved change.

  6. Re-measure

    Re-run the pipeline and publish the new numbers, including the ones that got worse.

Research and measurement, not betting advice. Every figure is computed by the code in this repository from the sources listed on each row; nothing is estimated by hand.
