METHOD & DATA

Reproducible, or it does not count.

The site is generated from committed code and committed data artefacts. Anyone can re-run the pipeline and get the same numbers, including the ones that are unflattering.

Pipeline

  1. Fetch - scripts/fetch_data.py downloads the nflverse release assets and records size and SHA-256.
  2. Profile - scripts/profile.py records columns, coverage and nulls per season.
  3. Prove conventions - scripts/diag_signs.py determines the spread sign convention from the data.
  4. Measure - market, model, correlation, luck, strategy and prop scripts write JSON only.
  5. Build - scripts/build_site.py renders these pages from that JSON; no value is typed by hand.

Each run commits data/derived/run_log.txt, so failures are visible in the repository rather than only in CI logs.

Known method limitations

  • Only closing lines are available. No timestamps or opening prices, so closing-line value cannot be measured - a limitation that makes every ROI here conservative rather than flattering.
  • The model is deliberately simple: transparent weighted least squares, no tracking data, no injury information, no opponent-adjusted efficiency.
  • Push handling follows the operator rulebook; games with a changed venue or abandoned status are not modelled.
  • No prop prices exist in the feed, so prop work stops at calibration.

Research and measurement, not betting advice. Every figure is computed by the code in this repository from the sources listed on the Source register page; nothing is estimated by hand.
