# Repository and decision-readiness audit — 2026-11-15

## Executive finding

The repository contains a live, reproducible research site and several useful validation/review desks. **It is not decision-ready for real-money betting or a rewards competition.** No candidate passes the current gates; no official market-price capture is present; the available official correlation set is team-standings-only; and the official replacement-depth evidence is blank. Two separate line-originator outputs disagree, and the root site still describes a staking-based tie-break that conflicts with the newer signal/staking desk.

This audit does not resolve any human policy choices or implement items from a suggestion queue. It records the evidence that exists, what is missing, a proposed measurable clearance condition, and links for review. A proposed clearance condition is a design recommendation—not an official NFL standard or an observed result.

## Evidence classes and freshness

- **Official:** NFL/NIST source pages linked in the committed `line-desk/data/sources.json` and NFL game pages/Game Books in `price-desk/data/sources.json`. Those registers say their sources were opened first-hand on 2026-11-14. This session did not fetch those pages. A separate merged [Week 10 injury-report record](../injury-report-w10/index.html) and its coordination log say another session read all eight chunks of the official [NFL Week 10 injury report](https://www.nfl.com/injuries/league/2026/REG10) at 2026-11-15 18:08 UTC; I did not repeat that fetch. The record flags limited coverage and no raw response hash. This audit does **not** claim a fresh independent external-source check.
- **Third-party:** nflverse community-maintained data. It is not an NFL-published price archive or an official record of which players actually started or were inactive.
- **Repository-derived:** counts and outputs computed from files in this repository. They can be re-run locally, but are not external source facts.

The repository therefore has at least two distinct clocks:

1. The main analysis inputs are through gameday **2026-11-01**, per `data/derived/manifest.json`.
2. The Line Desk's official NFL/NIST transcriptions have retrieval dates of **2026-11-14**, but cover only the weeks, games, standings fields and four-club injury sample described below. A separate Week 10 report page logs a different session's fetch at **2026-11-15 18:08 UTC**: 28 teams were listed, only 3 of 28 tables were transcribed row by row, four teams were absent with bye status unverified, and no raw-response hash was captured. The Week 9 lines are historical, not current live-slate lines.

## Site and repository irregularities

1. **Several dashboards repeat the same project scope.** The Review Board's own committed reconciliation reports 19 hubs scanned, 184 data files, 25 quantity-conflict rows covering 5 conflict labels, and 40 gate-definition conflicts. These are repository-derived reconciliation counts, not external NFL statistics. Until one source of truth is selected, do not average or silently choose between hub values. See [Reconciliation](../review-board/pages/reconciliation.html).
2. **Root navigation is not a clean single entry point.** Its current inventory records 37 nav targets and a duplicated “Suggestions hub” label. The root menu does not expose the Line Desk or Review Board, even though both contain the most recent requirements/review materials. Open PR #93 claims the root navigation files; this session did not edit them. A request to that owner is logged in `COORDINATION.md`.
3. **Model and leaderboard statements drift across pages.** Two originators differ by 1.5–9.0 points on the same 15 games. Root leaderboard HTML describes a gates-then-ROI ordering while the newer Line Desk ranks signal separately from staking. Both should be reconciled before a single competition page is treated as authoritative.
4. **Official vs third-party availability is easy to confuse.** `decision-hub/data/injuries.json` uses nflverse release records for injury, depth, roster and snaps. The merged `injury-report-w10/` record adds a prior-session official Week 10 report read, but only 3/28 team tables are row-transcribed; its counts are manual, four teams are absent with bye status unverified, and no raw-response hash exists. Neither source proves a complete point-in-time availability archive or an official 2nd/3rd/4th-string rank. The Line Desk correctly leaves replacement fields blank.
5. **The tracked virtual environment is repository noise.** `git ls-files .venv-b6` returns 6,240 tracked files. Open PR #97 claims the ignore/removal path; this session did not modify it.
6. **The strict official-only source requirement is not met across the full repository.** Many root analysis tables cite nflverse community data, and some other hubs cite club-supplied, scraped or sibling-repository data. Those sources are not the NFL's official site. The repository usually labels their tier, but the values are not blank everywhere; `tests/check_site.py` checks for a source link, not that the source is an official publisher. These values must not be represented as officially verified. This session did not blank shared table data because those outputs are owned by other integration scopes; the violation is recorded for review.
7. **Per-row source-check scope is not universal.** `tests/check_site.py` checked 231 HTML pages, 581 tables and 13,480 links; it explicitly notes 33 pages outside the root published build do not carry the root source column and are link-checked only by that checker. Sibling hubs have their own checks, but a passing local-link test is not verification that an external page still says what a row claims.
8. **Dependency setup is not self-explanatory in the sandbox.** System `python3 verification/recompute.py` failed because NumPy is absent. The same recomputation passed using the committed `.venv-b6` interpreter. A clean environment should install `requirements.txt`; relying on a tracked virtual environment is not a maintainable solution.
9. **The main root model is historical.** Its source manifest is dated 2026-11-02 and data through gameday 2026-11-01. Current Week 9 outputs are not a current line. The root page already contains a stale-snapshot warning, but the README and summary now make the date split explicit.

## Suggested discovery and review order

These are proposals, not implementation decisions. The [Review Board queue](../review-board/pages/suggestions.html), [Line Desk suggestion register](../line-desk/pages/suggestions.html) and [Price Desk suggestion register](../price-desk/pages/suggestions.html) contain the current item-by-item lists; the Review Board omits the latter two, and nothing below authorizes automatic implementation.

1. **Resolve the canonical dashboard and data owner.** Decide whether the root site, Line Desk or another hub is the primary entry point. Then add links rather than creating another duplicate dashboard. Before editing root navigation, coordinate with PR #93's owner.
2. **Decide the price-data policy.** Discover licensed/operator APIs and permitted historical coverage, timestamp precision, closing snapshot definition, prop/alternate-line coverage, pricing fees, redistribution rights and push/void rules. Keep market values blank until permission and capture are proven.
3. **Prove an official availability route for all 32 clubs.** The merged Week 10 page is only a partial prior-session capture (28 listed teams; 3 tables transcribed row by row; four absent teams not confirmed as bye teams). Inventory each club's dated chart and status, NFL Game Book access, official inactive evidence and snap-count provenance. Record a coverage matrix with explicit blanks; do not use jersey number, salary, experience or third-party depth order as a substitute.
4. **Make snapshots replayable.** Schedule immutable captures from Wednesday through kickoff. Store the source URL, UTC capture time, raw hash, parser version, row count and conflicts. Fail closed on missing fields/schema drift and publish freshness per source.
5. **Choose one line originator and freeze its contract.** Resolve the 15-game discrepancy. Store fair-line/probability output, all inputs and an as-of time for every bet type; pre-register a model version before the next holdout.
6. **Keep the competition paper-only until evidence qualifies.** Pre-register singles first. Add parlays/prop combos only after directly validated joint probabilities and settlement rules. Use chronological train/validation/final-holdout seasons, proper scores, uncertainty, random/favorites-only controls and multiplicity correction. Keep staking separate; do not rank on realized season ROI.
7. **Set reward and access policy separately from model skill.** Confirm whether any prize exists, who may participate, and which jurisdiction/terms apply. Until there is a funded, reviewed pool, publish “no rewards payable.”
