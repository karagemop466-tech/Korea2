VALIDATION GATES

Twelve tests. Ten exist somewhere; two are the project's own gaps.

The root hub publishes ten gates and this board proposes two more that its data cannot satisfy today (depth quality, correlation stability). Nothing is re-numbered: the mapping is shown per row so the two sets cannot be confused.

Gates

Gate set proposed for the whole repository

A gate that exists in the root register is enforced by that pipeline; a proposed gate is a design item the owner has to accept first.
IDNameRequirementWhy it existsRelation to the root setSource
G1Point-in-time integrityEvery input provably timestamped before kickoff; feature builders refuse future-dated rows.This is the project's dominant failure mode: an 'injury signal' built by re-reading the live report today is hindsight, and every hub that skipped it produced an unbeatable result.also in the root set, same idLine Lab committed pipeline results (data/derived)
G2Sample floor before the test, not afterDeclare n and the effect size; a candidate with fewer settled bets than the power analysis requires is reported as 'insufficient', never as 'passed' or 'rejected'.The repository's own power table shows how large 'enough' is; without it a 137-bet strategy looks like a finding.also in the root set, same idLine Lab committed pipeline results (data/derived)
G3Correction for the number of things triedBenjamini-Hochberg across the whole batch, plus a deflated-Sharpe-style adjustment for variants of the same idea.A leaderboard where 31 variants compete will produce a winner by construction.also in the root set, same idLine Lab committed pipeline results (data/derived)
G4Interval, not a point estimateEvery ROI, win rate and coefficient published with a bootstrap or Wilson interval; a claim whose interval crosses the break-even line is labelled 'not distinguishable from zero'.It stops a positive number from being read as an edge.also in the root set, same idLine Lab committed pipeline results (data/derived)
G5Settlement rules written down firstPush, void, no-action, each-leg-loses and altered-leg rules recorded with the operator source and effective date before any price is used.Different hubs currently disagree on push handling, which moves win rates by more than most candidate edges.also in the root set, same idLine Lab committed pipeline results (data/derived)
G6Market benchmark requiredEvery accuracy claim must be compared with the closing market on the same games, not with a naive baseline.The site's own headline result is that the close beats the model; a claim that only beats 'average yards' is not a claim about betting.also in the root set, same idLine Lab committed pipeline results (data/derived)
G7Out-of-sample, walk-forward, untouched holdoutFit on the past, test on the future, and reserve a final window no run is allowed to touch more than once.It is the only part of the design that removes the researcher's own luck.also in the root set, same idLine Lab committed pipeline results (data/derived)
G8Luck removal / variance controlsScore the leaderboard on CLV and Brier-type skill against the market with a minimum-bet floor and a shrinkage factor; season-length results may not promote a strategy.'Remove luck from the equation' is a requirement, and ROI at small n is mostly luck.also in the root set, same idLine Lab committed pipeline results (data/derived)
G9Executable price, no repriceSettle at the price a bettor could actually have taken; a multi-leg bet may not be repriced to a more favourable combination of legs.An audit of a sibling lab found exactly that in its price-sensitivity gate, which inflated its results.also in the root set, same idLine Lab committed pipeline results (data/derived)
G10Reproducible and source-disciplinedRebuild from a clean checkout reproduces every published number; every table row links a source; unverifiable values stay blank and appear on the flagged page.It is the project's stated rule, and the audit trail shows where the site breaks it.also in the root set, same idLine Lab committed pipeline results (data/derived)
G11Depth and opponent adjustment (proposed, not implementable today)Any 'backup quality' or 'defensive deficiency' claim must name the source that defines the string depth, or it is not a claim.Included so the requirement in the brief is visible as a gate, not as a vague aspiration. No source currently satisfies it.proposed here - no implementationThis hub's programme register
G12Correlation-stability check for parlays (proposed)A parlay claim may not rest on a coefficient measured on a different leg definition than the one being bet, and the coefficient must be stable across seasons.The Reconciliation page shows the same label carrying several different coefficients across hubs; today that would pass unnoticed.proposed here - no implementationThis hub's programme register
