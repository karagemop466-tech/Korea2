RECOMMENDED PATH

Choose the order first; the content can wait.

The phases are ordered by dependency, not by effort. Each one is a decision with an exit test, so "done" is a checkable condition rather than an opinion.

Governance

Review rules for this board

Each rule exists because the repository's history shows the failure it prevents.
#RuleWhy
1Nothing is implemented from this board by the agent that wrote it. A cluster moves only when the owner records approve / reject / modify.The brief is to review suggestions and choose the path before changes are made; several prior sessions implemented their own proposals, which is how the repository grew to the state described on the Hub map page.This hub's programme register
2A rejected suggestion stays on the board with its status and date; it is not deleted.The same idea has already been re-proposed by four sessions that did not see the earlier decision.This hub's programme register
3Two suggestions that touch the same file may not be implemented in the same change.Every session in this repository shares COORDINATION.md, and merge conflicts there are the dominant cost of parallel work.This hub's programme register
4A cluster may not be approved while a question inside it is 'unanswered', unless the approval explicitly says the gap is accepted.That is what turns 'we do not know' into a decision instead of an accident.This hub's programme register
5Every published value keeps its class: official fact, computed from a third-party feed, or proposal.The audit trail showed values quoted as verified that were model outputs, and vice versa.This hub's programme register
What this page deliberately does not do
It starts none of the phases. Every phase touches files owned by other sessions - root navigation, sibling hubs, CI - and the board rule is that shared outputs change only in a final integration pass. An approval recorded here is the input to that pass.
