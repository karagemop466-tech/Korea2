How to choose a path without implementing anything.

A short, ordered process. Each step says what to read, what to decide, and what happens next. The site is a decision aid; the decisions are recorded here so an implementation session can act on them without guessing.

The process

  1. Read the questions register, blocked items first. Anything blocked cannot be decided well yet — it needs data, not opinion. Open it.
  2. Answer the three decisions. Measurement vs picks; rank vs prize; which weakness first. Each has the evidence for and against. Open them.
  3. Adopt suggestions selectively. Start with the low-cost high-impact set (S-02, S-01, S-05). Each is one to two days and removes a specific way the site can mislead. Open them.
  4. Only then commission code. A suggestion with a blocking question is not actionable; implementing it produces a number nobody can defend.
  5. Re-audit. Run python decision-hub/scripts/audit_root.py and check that nothing that used to reproduce has stopped. Open the audit.

What a recorded decision needs

  • The option chosen, and the date.
  • Which questions were answered and which were accepted as open.
  • Which suggestion list follows from it.
  • The evidence that would make the decision wrong later (so it can be revisited honestly).

Until a decision is recorded, the recommendation is the default: keep the site a measurement system, keep rewards as a rank, and fix the ATS statistic first.
