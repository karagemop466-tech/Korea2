Bet definitions

S-11

Write the settlement and void rules down before pricing anything

impact 3 low cost proposed
Problem in the current site
Parlay and prop settlement differ by operator (push handling, void legs, minimum leg count, same-game restrictions). A strategy that looks profitable under one rulebook can be unprofitable under another.
Suggestion
Adopt one regulator-filed rulebook as the settlement standard for every backtest, cite the edition, and re-price the whole backtest if the edition changes. The repository already cites a DraftKings Massachusetts filing that the regulator lists as obsolete; pin the active edition.
Evidence
FL-11 on the root flagged page: the cited 8.1.24 edition is archived as obsolete; the active edition is the one approved 10.7.26.
Risk
A single operator's rules will not generalise; the choice must be stated as a limitation.

impact 3 low cost proposed
Problem in the current site
QB-to-WR1 is published as a single number (0.562). Parlay pricing under a Gaussian copula is extremely sensitive to the copula parameter, so a point estimate understates the uncertainty in the joint probability.

Add a bootstrap interval for every pairwise correlation and propagate it into the SGP joint probability, so the parlay price carries an interval too.

Track depth lost per team-week and test it against the line before using it

impact 5 medium cost in_progress
Problem in the current site
The requirement is to know when a defence or offence is on its 2nd, 3rd or 4th string. Nothing in the repository joined the injury report to a depth chart, so the claim in prose was unsupported.
Suggestion
Ship the tracker built this session: every reported Out/Doubtful player is placed on the club depth chart as 1st/2nd/3rd string, and each team-week is scored (weighted depth lost = sum of 1/rank). Statistical validity

S-02

Replace the pooled ATS 'coin-flip test' with a one-sided test

impact 5 low cost proposed
Problem in the current site
The headline '50.0%, p = 1.0' ATS result is an arithmetic identity: the sample contains every game twice, once per side, so exactly half the rows win. It cannot detect a market tilt in either direction, yet it is presented as evidence that the market is efficient.
Suggestion
Use one observation per game (home cover rate = 48.91%, 95% CI 47.73-50.09%, two-sided p = 0.073 on 6,892 decided games). Report the interval, not just the point. Keep the pooled number only if it is labelled as an identity.
Evidence
decision-hub/data/root_audit.json flags FL-DH-01 and ats_honest; the arithmetic is reproduced from data/derived/games.csv.gz.
Risk
The honest test is closer to significance, which invites over-reading. Publish the CI, not just the p-value.

1 days

S-06

Add negative controls to every strategy batch and publish them next to the candidates

impact 4 medium cost proposed
Problem in the current site
A screen that rejects everything looks rigorous, but it looks identical to a screen that is simply broken. Two controls already exist in the leaderboard; they are not shown as a diagnostic.
Suggestion
Run a known-losing control (random side) and a known-winning control (a deliberately clairvoyant bettor using the actual result) through the same ten gates. The random control must fail and the clairvoyant control must pass; if either does not, the gate screen is mis-wired and no verdict on a real candidate is meaningful.
Evidence
data/derived/leaderboard.json has 9 entries; two are family 'control'. The clairvoyant positive control is not present.
Risk
A clairvoyant control validates the plumbing only; it says nothing about whether a real edge exists.

Strategy evaluation

S-03

Add closing-line value as the headline skill metric

impact 5 high cost proposed
Problem in the current site
ROI over a season is dominated by variance: with a 300-bet sample the interval on ROI is roughly +/- 12 percentage points, which is wider than any edge being hunted. CLV measures skill against the market's own final opinion and needs far fewer observations.
Suggestion
Store a timestamped price at decision time, compute (decision price - closing price) per bet, and rank strategies by mean CLV with a bootstrap interval. Treat positive CLV with a losing record as skill, and negative CLV with a winning record as luck.
Evidence
The repository stores only the closing line (data/derived/games.csv.gz has spread_line, away/home_spread_odds, total_line but no open line and no timestamp); flagged FL-DH-08.
Risk
Requires a price feed that does not exist yet. Until then, CLV can only be computed for bets logged live going forward.

15 days
